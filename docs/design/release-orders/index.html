Release Orders Redesign

The stage between allocation and the truck turns allocated orders into physical pick lists and packing slips for the warehouse. It's been renamed. Below are three ways the screen could look and flow, drawn with your own orders.

Today Who uses it A · Release list B · Waves C · Board Compare Recommendation
Done: "Pick & Pack" is now "Release Orders"
  • The menu tile, page title, intro, back links and permission names all use the new name.
  • The button on each order is now Release Order.
  • The allocation outcome now reads "send to Release Orders".
  • The Open Picks column is now "Release".

These things stay the same: the web address (/#/pick-pack), so bookmarks still work, and the status an order gets after release ("Pick & Packed"). That status is misleading, since nothing has been picked yet. Renaming it to Released is a small follow-up.

What the stage looks like today

  • One order at a timeEach release takes a page visit, a scroll to the bottom and a trip back. At about 150 orders a day that adds up to 150 round trips, and the day simulation already showed analysts as the bottleneck.
  • No way to prioritizeThe review list shows S.O., P.O., customer and status. It leaves out ship date, carrier, size, weight and whether allocation is full or partial, so it's hard to tell which order should go first.
  • Two jobs on one pageThe analysts' decision (what goes) and order entry's task (print it) sit stacked in one scroll, and printing starts with every order selected.
  • No view of the floorAfter printing, an order disappears to Open Picks. The capacity banner shows a percentage, but it isn't tied to the orders you're about to release.

Who uses this stage, and for what

Each option is judged against these jobs. The roles are the ones set up in round 2.

A

Release list

Recommended now

This keeps the page you know, reorganized around decisions. There's one table per stage, and each tab belongs to one role. The analyst tab carries the information needed to choose, lets you release many orders at once, and opens any order inline so you can trim a line without leaving the list.

How it flows

  1. An analyst opens Ready to release. It's filtered to orders that ship today and sorted by ship date, then by customer.
  2. They tick the orders to send. The bar totals lines, units and pounds, so they can compare against the capacity figure before committing.
  3. To release part of an order, they expand its row and lower the quantity on any line. The full review page is still one click away.
  4. Pressing Release N orders moves those orders to the second tab. A quantity changed on a line releases only that line's quantity.
  5. Order Entry works the Released · print documents tab. They pick pick lists, packing slips or both, and print. Nothing is selected until they choose.
  6. Printed orders move to On the floor. That tab is read-only, with time since printing, and Logistics carries on from Open Picks as today.

Good

  • Cuts about 150 page visits a day to a few batches.
  • Ship date, weight and partial allocation are visible when choosing.
  • Each tab maps to one role and its permission.
  • Very little new to learn.

Watch

  • It releases order by order. The warehouse still walks each order separately.
  • A bulk release needs a clear undo; unallocating from the Released tab covers it.
What it takes: about 2–3 daysNothing new in the database. The order list needs ship date, carrier, line, unit and weight totals, and a full/partial flag, all of which already exist on the order. Add one bulk-release endpoint that runs the existing per-order release for each order under the same checks. Tabs, filters and the inline editor are frontend work.
B

Waves

Best next step

Release in batches (waves) sized to what the floor can pick before the next truck. A wave prints as one combined pick list sorted by bin, so a picker walks each aisle once for several orders. Every order still gets its own packing slip. This is how most distribution warehouses run the step.

How it flows

  1. The analyst filters by the next truck pickup (for example, FedEx Freight at 2:00 PM) and ticks the orders that should make it.
  2. The wave card shows totals, an estimated pick time, and the floor load after release. If the pick won't finish before the truck, it says so.
  3. Release wave & print releases every order and queues one combined pick list by bin, plus a packing slip per order. It can also be saved as a draft for Order Entry to print.
  4. The Today's waves list tracks each wave: waiting to print, printed, picking, picked and at the dock. The warehouse lead marks progress.
  5. Logistics sees whole waves at the dock and confirms them against the pickup.

Good

  • Much less walking on the floor, especially for the small orders, which are about half of all POs.
  • Releases are timed to trucks, not to when someone got to the list.
  • Floor load becomes a planning number, not a warning.

Watch

  • Needs data the system doesn't hold yet: bin locations and carrier pickup times.
  • A combined pick list needs a sort-to-order step at packing.
  • The 20+ line key-account orders usually go as their own wave anyway.
What it takes: about 2 weeks, after the data existsNew: a bin location on each item, a pickup schedule per truck line, a Wave record that links orders, a picker-count setting, and a combined pick list print. The estimated pick time needs a few weeks of timing data before it's trustworthy.
C

Board

Not recommended as the main screen

One card per order, in columns from allocation to the dock. Each column is one step and one role's button. The "On the floor" column has a limit, which replaces the percentage in the capacity banner with a count you can see.

How it flows

  1. The analyst presses Release on a card. It opens the order's release page for line changes, or releases in full.
  2. The card moves to Released · print. Order Entry presses Print for that order's documents.
  3. Printed cards sit in On the floor with a timer. If the column passes its limit, analysts hold new releases.
  4. The warehouse lead marks the card picked. Logistics presses Confirm shipped in the last column or on Open Picks.

Good

  • Best at-a-glance view for the director, logistics and customer service.
  • Bottlenecks are obvious: a column that keeps growing is the problem.

Watch

  • Doesn't scale to your volume. About 150 orders a day means columns of 40+ cards.
  • Back to one order per click, the problem Option A fixes.
  • Cards have no room for lines or weight, which are the details analysts decide on.
  • Duplicates Open Picks.
What it takes: about 1 weekUses existing statuses plus a "picked" mark. Works better as a read-only dashboard view added next to A than as the working screen.

Recommendation

Build A now and grow it into B. A fixes today's real cost, which is analyst clicks and releasing without knowing ship dates or weight, and it needs nothing new in the database. B's gains depend on bin locations and pickup times, which are worth collecting anyway.

  1. Now: Option A. Add the bulk-release endpoint and rename the "Pick & Packed" status to "Released".
  2. Meanwhile: add a bin location to items (the Inventory import could fill it) and a pickup time on each truck line in the Routing Guide.
  3. Then: add a "Wave" action to A's Ready tab that groups the selected orders, prints one bin-sorted pick list, and tracks the wave. That makes it Option B without a second screen.
  4. Optional: C as a read-only pipeline view on the Dashboard for the director and customer service.
